# AI 개선 계획 (백로그)

> **상태: 계획만 있고 구현하지 않았다.** 핵심 기능(로컬 2인, 기본 AI, UI·아트, 배포)이 안정된 뒤에 진행한다. 이 문서의 항목은 `docs/03_REQUIREMENTS.md`의 E04(AI 개선)와 P2(AI 난이도 선택)에 해당한다.

## 1. 현재 AI(Day 5 최소 구현)가 하는 일
구현 파일은 `js/ai.js`다. 사람과 같은 `{ move, placeBomb }` 액션만 만들고 게임 상태를 직접 바꾸지 않는다.

1. **위험 지도**(`buildDanger`): 칸마다 폭발 위험 구간 `[시작, 끝]`을 계산한다. 연쇄 폭발은 먼저 터지는 시각으로 전파하고 안전 여유 0.15초를 둔다.
2. **시간 고려 탐색**(`search`): 0.16초/칸 이동으로 도착 시각을 계산하고, 도착 후 머물러도 안전한 칸만 목적지로 삼는다.
3. **판단 순서**(`decide`): ① 위험하면 가장 가까운 안전한 칸으로 탈출 → ② 안전하면 부적 설치 지점 선택(상자 1개 10점, 상대가 십자 범위에 있으면 60점, 거리 감점)하고 설치 후 탈출 경로가 있을 때만 설치 → ③ 노릴 곳이 없으면 상대 쪽으로 접근.
4. 0.2초마다 재판단하되 새 부적·폭발이 생기면 즉시 재판단한다.

현재 수준은 "상자와 폭발은 잘 피하고, 가만히 있거나 불규칙하게 걷는 상대는 이기지만, 움직임을 읽는 사람에게는 약한" AI다(시뮬레이션: 정지 상대 15/15 승, 랜덤 상대 40/40 승, AI끼리 승 12·무 8).

## 2. 한계
| ID | 한계 | 영향 |
|---|---|---|
| L1 | 상대의 **현재 칸**만 노린다. 이동 방향·도망 경로를 예측하지 않는다 | 움직이는 사람에게 폭발이 자주 빗나간다 |
| L2 | 길목을 막거나 도망갈 칸을 없애는 몰아넣기 전략이 없다 | 공격이 단발성이다 |
| L3 | 체력 2·시간 종료 시 체력 비교 규칙을 모른다 | 체력이 앞서도 공격하고, 뒤져도 수비한다 |
| L4 | 상대 무적(1.5초) 상태를 구분하지 않는다 | 무적 중인 상대에게 부적을 낭비한다 |
| L5 | 상자가 남아 있으면 상대 접근 동작(3단계)이 거의 쓰이지 않는다 | 상대와 거리를 좁히는 데 소극적이다 |

## 3. 개선 항목
### I1. 상대에게 적극 접근 (L5)
- **내용:** 설치 지점 점수에 "상대와의 거리"를 반영해 상자가 남아 있어도 상대 쪽으로 이동하게 한다. 상대와 가까워지면 상자보다 상대를 우선한다.
- **구현 접근:** `decide`의 후보 점수식에 상대 맨해튼 거리(또는 경로 거리) 가중치를 추가하고, 가중치는 상수로 분리해 난이도(I4)에서 조절한다.
- **수용 기준:** 정지 상대를 격파하는 평균 시간이 짧아지고, 자살(스스로 맞음)·벽 통과·장시간 정지가 늘지 않는다.

### I2. 상대 이동 예측과 몰아넣기 (L1, L2)
- **내용:** 상대가 폭발 전에 갈 수 있는 안전한 칸 집합을 계산하고, 그 집합이 작아지는 자리에 부적을 놓는다. 탈출 칸이 0이면 큰 보너스를 준다.
- **구현 접근:** 상대 위치에서 같은 시간 고려 탐색(`search`)을 돌려 "상대 탈출 가능 칸 수"를 구한다. 후보마다 계산하므로 후보 수(`MAX_ESCAPE_CHECKS`)와 판단 주기를 지켜 CPU 부하를 제한한다.
- **수용 기준:** 도망치는 스크립트 상대에 대한 승률이 I1 단독보다 높다. 판단 1회가 프레임을 눈에 띄게 지연시키지 않는다(목표: 5ms 이하, 측정해서 기록).
- **주의:** 복잡도가 가장 높다. 사람처럼 보이는 행동을 목표로 하고, 항상 이기는 AI는 목표가 아니다.

### I3. 상태 인식: 무적·체력·시간 (L3, L4)
- **내용:**
  - 상대가 무적이고 남은 무적 시간이 폭발 도달 시간보다 길면 상대 적중 보너스를 주지 않는다.
  - 체력이 앞서고 남은 시간이 적을 때는 수비 위주(안전한 칸 유지, 상자 파괴는 위험 낮을 때만), 뒤질 때는 공격 가중치를 올린다.
- **구현 접근:** `gain`과 후보 점수에 `me.hp`, `enemy.hp`, `enemy.invincible`, `game.timeLeft`를 입력으로 추가한다. 새 입력은 읽기 전용이다.
- **수용 기준:** 무적 상대에게 낭비하는 부적 수가 줄고, 시간 종료 직전 체력 우세 판에서 AI가 피격되는 비율이 줄어든다.

### I4. 난이도 선택 (P2)
- **내용:** 쉬움 / 보통 / 어려움을 파라미터 표로 구분한다. 규칙은 모든 난이도에서 동일하다.

| 파라미터 | 쉬움 | 보통(현재) | 어려움 |
|---|---|---|---|
| 재판단 주기 | 0.35초 | 0.2초 | 0.12초 |
| 안전 여유 | 0.3초 | 0.15초 | 0.1초 |
| 상대 추적 가중치(I1) | 낮음 | 중간 | 높음 |
| 몰아넣기 예측(I2) | 사용 안 함 | 약하게 | 사용 |
| 상태 인식(I3) | 사용 안 함 | 사용 | 사용 |

  표의 수치는 시작값이며 시뮬레이션으로 조정한다.
- **불변 조건:** 어떤 난이도에서도 ① 벽·바위·상자를 통과하지 않고 ② 탈출 경로가 없으면 부적을 설치하지 않고 ③ 사람과 같은 행동 API만 쓴다. 쉬움은 "실수"가 아니라 "느린 반응과 소극적 공격"으로 구현한다.
- **UI:** 모드 선택 화면(Day 6)이 있어야 하므로 그 이후에 `AI 대전` 선택 뒤 난이도 선택을 붙인다.
- **수용 기준:** 같은 스크립트 상대에 대해 승률이 어려움 ≥ 보통 ≥ 쉬움이다.

### I5. 아이템 획득(아이템 구현 이후)
- 아이템 기능을 넣은 뒤 AI가 아이템을 주워 능력을 올리도록 한다(문서 04의 A4). 아이템 규칙(최대치 처리, 폭발로 인한 아이템 파괴 여부)이 확정된 뒤에 설계한다.

## 4. 진행 순서와 조건
