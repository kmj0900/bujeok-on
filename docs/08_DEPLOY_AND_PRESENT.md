# 배포 및 발표 가이드

## 1. Render Static Site
1. GitHub 저장소에 정적 웹 프로젝트 업로드.
2. Render에서 **Static Site** 생성 후 저장소 연결.
3. 빌드 단계가 없는 순수 정적 프로젝트라면 빌드 명령 없이 구성하고 게시 디렉터리를 저장소 루트(`.`)로 설정(배포 UI 요구사항 확인).
4. 배포된 URL에서 `index.html`, JS 모듈, 이미지 파일이 모두 정상 로드되는지 확인.
5. 다른 브라우저/노트북에서도 새로고침·대전·재대결 테스트.

**배포 준비 상태(2026-11-25):** 빌드 단계가 없다. 모든 경로가 상대 경로이고 외부 주소·서버 코드가 없다. `.gitignore`가 `_to_delete/`(미리보기 흔적)를 제외한다. Render 설정: **Static Site**, Build Command 비움(또는 `echo ok`), **Publish Directory `.`**, Branch `main`. 올릴 파일은 `index.html`, `style.css`, `js/`, `assets/`가 핵심이고 `docs/`, `tests/`, `tools/`는 같이 올려도 동작에 영향이 없다.

**주의:** Render Static Site는 브라우저에서 게임과 AI를 실행한다. URL을 공유해도 두 노트북이 같은 방에서 대전하지는 않는다.

## 2. 발표 자료(9장 예시)
1. 프로젝트 소개: 부적소동: 비밀 수련장
2. 주제 선정 이유: 짧은 기간에 배포 가능한 캐주얼 게임
3. 승급 시험 세계관 및 게임 스토리
4. 로컬 2인/AI 대전, 부적·폭발·봉인 핵심 기능
5. 기술 스택 및 공통 게임 엔진·맵 데이터 구조
6. 바이브 코딩 프롬프트와 개발 단계
7. 실제 오류와 해결 사례(전후 비교)
8. Render URL 시연(로컬 2인, AI)
9. 결과·한계·추가 맵/온라인 대전 확장 방향

## 3. 시연 시나리오(권장)
- URL 접속 → 모드 선택 → AI 대전 시작.
- 캐릭터 이동 → 부적 설치 → 상자 파괴/폭발 회피.
- 승패 결과 및 재대결 보여주기.
- 로컬 2인 모드도 짧게 시연(가능하면 보조 시연자 확보).
- 추가 맵을 구현한 경우에만 맵 선택 시연.

## 4. 개발 과정 기록
각 단계마다 AI에 입력한 요청, AI가 변경한 파일, 실제 실행 결과, 오류와 해결 과정을 캡처/기록한다. 구현하지 않은 기능을 발표에서 완성했다고 말하지 않는다.
