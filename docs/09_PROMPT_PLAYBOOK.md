# 바이브 코딩 프롬프트 플레이북

## 공통 프롬프트(작업 시작 시)
> 이 프로젝트의 `AGENTS.md`, `README.md`, `docs/01_GAME_DESIGN.md`, `docs/02_TECHNICAL_DESIGN.md`, `docs/03_REQUIREMENTS.md`를 먼저 읽어줘. 이번 요청의 범위만 구현하고, 기존 게임 규칙과 기술 스택을 유지해줘. 작업 전에 변경 파일과 접근 방법을 설명하고, 작업 후 실행/테스트 방법과 미완료 항목을 알려줘. 테스트하지 않은 항목을 테스트했다고 주장하지 마.

## 프롬프트 1 — 프로젝트 초기화
> HTML/CSS/Vanilla JS ES Modules와 Canvas 2D로 프로젝트를 구성해줘. 15×13 타일(32px) 깊은 숲 수련장을 임시 도형으로 렌더링하고, 정적 호스팅 가능한 구조로 만들어줘. 맵 데이터와 렌더링 코드를 분리해줘. 아직 공격/AI는 구현하지 마.

## 프롬프트 2 — 이동·충돌
> `docs/02_TECHNICAL_DESIGN.md`의 공통 타일 규칙에 따라 흑영(WASD), 녹림(방향키)의 동시 이동을 구현해줘. 외곽·SOLID·BREAKABLE과 충돌해야 하고 시작 주변은 안전해야 해. 입력으로 페이지가 스크롤되지 않게 해줘.

## 프롬프트 3 — 부적과 폭발
> 부적 설치(Space/Enter), 2.5초 퓨즈, 0.4초 십자 폭발(기본 2칸), 고정벽 차단, 상자 파괴, 연쇄 폭발을 구현해줘. 부적 소유자도 피해를 입고, 설치한 칸에서 나간 후 재진입할 수 없게 해줘. 같은 폭발의 중복 처리를 방지해줘.

## 프롬프트 4 — 승패·상태
> 봉인 2초 후 탈락, 180초 타이머, 동시 탈락 무승부, 일시정지, 결과 화면과 재대결을 구현해줘. 재대결 시 게임 상태가 완전히 초기화되어야 해. `docs/07_TEST_PLAN.md` 기준으로 확인 방법도 제시해줘.

## 프롬프트 5 — AI 상대
> `docs/04_AI_BEHAVIOR.md`를 기준으로 규칙 기반 AI를 구현해줘. AI는 사람과 동일한 `applyAction` 인터페이스를 사용하고, 장애물 회피·폭발 위험 예측·안전한 부적 설치를 수행해야 해. 서버/API/머신러닝 모델은 사용하지 마.

## 프롬프트 6 — UI/그래픽
> 현재 동작하는 로직을 유지하면서 메인·모드 선택·HUD·결과 화면을 제작해줘. 픽셀아트 스타일로 표현하되 이미지가 없어도 대체 도형으로 플레이할 수 있게 해줘. 게임 규칙을 바꾸지 마.

## 프롬프트 7 — 추가 맵(선택)
> `docs/05_ART_DIRECTION.md`에 따라 폭포 계곡 수련장 맵을 추가해줘. **기존 게임 엔진을 복제하거나 수정하지 말고**, 공통 타일 규칙을 유지하면서 맵 데이터와 에셋만 추가해줘. 폭포와 물은 장식이며 특수 이동/폭발 효과는 없어. 맵별 시작점·통로·AI 경로를 검증해줘.

## 프롬프트 8 — 배포 점검
> Render Static Site에 배포할 수 있도록 정적 경로와 ES Module 로딩을 점검해줘. 새 브라우저에서 로컬 2인과 AI 대전이 동작하는지 확인할 테스트 절차를 작성해줘. 실제 배포를 수행하지 않았다면 배포 성공이라고 표현하지 마.

## 프롬프트 9 — 경계 상황 수정(필수)
> `docs/11_EDGE_CASES.md`, `docs/12_MAP_SCHEMA.md`, `docs/07_TEST_PLAN.md`를 읽고 구현과 명세가 충돌하는 부분을 찾아줘. 특히 같은 틱 폭발 스냅샷, 부적 설치 칸 재진입, 봉인 중 동시 탈락, 탭 전환 시 타이머, 상자 후보 35% 계산을 검증해줘. 실제 실행하지 않은 테스트는 미실행으로 표시하고, 수정은 최소 범위로 해줘.
