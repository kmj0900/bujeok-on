# 기술 설계 및 아키텍처

## 1. 원칙
**공통 게임 엔진 + 공통 타일 규칙 + 맵별 데이터·이미지.** 맵마다 `player`, `bomb`, `ai` 로직을 복사하지 않는다.

## 2. 프로젝트 파일 구조(권장)
```text
ninja-arcade/
├── index.html
├── style.css

│   ├── maps.js       # 테마별 맵 데이터
```

## 3. 좌표와 화면
- 격자: **15열 × 13행**, 타일 **32×32px**.
- 내부 Canvas: **480×416px**(HUD는 Canvas 밖 또는 별도 레이아웃).
- CSS 확대: 1.5~2배 권장, 픽셀아트는 `image-rendering: pixelated`.
- 외곽 1칸 벽이면 내부는 13×11=143칸.
- 17×13은 테스트 결과 좁을 때만 검토. 최초 구현 중간에 맵 크기를 변경하지 않는다.

## 4. 타일 유형과 레이어
```js
const Tile = Object.freeze({ FLOOR: 0, SOLID: 1, BREAKABLE: 2 });
```
- `FLOOR`: 통행 가능, 폭발 통과.
- `SOLID`: 통행 불가, 폭발 차단, 파괴 불가.
- `BREAKABLE`: 통행 불가, 폭발이 해당 칸에서 멈추고 파괴 가능.
- `DECORATION`은 **별도 렌더링 레이어**로 관리하며 물리 타일 종류로 취급하지 않는다.
- 부적은 타일이 아니라 별도 동적 객체. 타일과 부적 충돌을 모두 검사한다.
- 폭포·물웅덩이·절벽은 우선 **전투 영역 바깥의 장식**으로만 배치. 물속 이동, 미끄러짐, 폭발 감쇠 등 새 타일 규칙은 도입하지 않는다. (2026-11-25: 폭포 계곡은 맵 위협 `current`로 줄 위의 닌자를 밀어내는 물살을 둔다. 타일 규칙이 아니라 위협이고, 피해는 없다.)

## 5. 맵 데이터 계약(예시)
```js
export const MAPS = {
  forest: {
    id: 'forest', name: '깊은 숲 수련장',
    width: 15, height: 13, tileSize: 32,
    theme: {
      floor: 'grass', solid: 'mossy-rock',
      breakable: 'wooden-crate', backdrop: 'forest'
    },
    spawnPoints: [{x:1,y:1}, {x:13,y:11}],
    solidCells: [], // 외곽 벽 + 내부 고정 장애물 좌표
    crateSpawnRate: 0.35, // 허용된 후보 칸 중 35%
    decoration: [] // 게임 판정에 영향 없는 장식
  }
};
```
`solidCells`는 위 예시에서 빈 배열로 둔 **스키마 예시**다. 실제 맵 로더는 외곽 벽·고정 장애물 좌표를 구성하고, 중복 좌표·범위 밖 좌표·시작 지점 막힘을 검증해야 한다.

### 맵 공통화 주의점
- 이미지 키만 교체한다고 자동으로 공정한 맵이 되지 않는다.
- 맵별로 `solidCells`, 시작 지점, 상자 후보 영역, 장식, 테마를 별도 관리한다.
- 동일한 `Tile` 판정 API를 `player.js`, `bomb.js`, `ai.js`에서 재사용한다.
- 각 맵은 양쪽 시작점의 안전 영역과 AI 경로 탐색 가능성을 검증한다.
- 무작위 상자는 배치 가능한 칸의 약 35%로 시작, 테스트 후 30~40% 범위에서 조정한다.
- 시작 지점과 인접한 최소 2개 통행 칸은 비워둔다. 전체 통로 연결성은 생성 후 검사하거나 재생성한다.

## 6. 상태 모델
- 게임: `MENU`, `COUNTDOWN`, `PLAYING`, `PAUSED`, `RESULT`.
- 플레이어: `NORMAL`, `SEALED`, `ELIMINATED`.
- 게임 상태 예: `{ mode, mapId, timeLeft, players, bombs, explosions, crates, items, phase, result }`.
- 결과 판정은 매 프레임 일관된 순서로 한 번만 수행한다.

## 7. 게임 루프
`requestAnimationFrame` + deltaTime. 게임 시간이 흐를 때만 이동/AI/부적/폭발/봉인/타이머를 업데이트한다. 렌더링은 별도 함수. 탭 비활성화 시 자동 일시정지 권장.

## 8. 조작과 AI의 공통 인터페이스
```js
// 키보드와 AI 모두 동일한 액션을 생성
// { move: 'up'|'down'|'left'|'right'|null, placeBomb: boolean }
function applyAction(player, action, gameState, dt) { /* ... */ }
```
AI는 게임 상태를 읽고 행동을 결정할 뿐, 플레이어 좌표를 직접 변경하거나 부적을 임의 생성하지 않는다.

## 9. 판정 순서 권장
입력/AI 행동 → 이동·충돌 → 부적 설치 → 부적 타이머·연쇄 폭발 → 상자 파괴·아이템 생성 → 폭발 피해/봉인 → 봉인 타이머 → 승패/시간 종료 → 렌더링.
같은 프레임 내 동시 탈락·연쇄 반응은 별도 테스트로 검증한다.

## 10. 배포
정적 파일만 Render Static Site로 배포. 브라우저가 게임과 AI를 로컬에서 실행한다. URL 공유는 가능하지만 서로 다른 기기 사이의 온라인 대전은 불가능하다.

## 11. 프레임 독립성·결정적 업데이트
- 고정 시뮬레이션 스텝 `1/60초`를 권장하고 `requestAnimationFrame`은 화면 렌더링에만 사용한다. 실제 경과 시간을 누적해 여러 스텝을 처리하되, 프레임 복귀 시 누적량은 최대 `0.25초`로 제한한다.
- 타이머는 게임 스텝으로만 감소시킨다. `Date.now()`나 `setTimeout`으로 퓨즈·봉인·라운드 종료를 처리하지 않는다.
- 탭 숨김 또는 창 포커스 상실 시 `PAUSED`로 전환하고 누른 키를 모두 해제한다. 복귀 시 사용자가 명시적으로 계속하기를 선택한다.
- 폭발 처리: (1) 만료 부적 수집 (2) **틱 시작 장애물 스냅샷**으로 모든 연쇄 폭발 범위 계산 (3) 영향을 받은 상자·부적 집합 계산 (4) 일괄 반영 (5) 활성 폭발 피해 적용. 연쇄 폭발은 큐와 `explodedBombIds` 집합으로 중복 방지한다.
- 종료는 한 명이 봉인되는 즉시 처리하지 않는다. 같은 틱 피해 및 활성 부적/폭발에 의한 후속 피해를 고려해 `docs/01_GAME_DESIGN.md`의 승패 규칙대로 정산한다.

## 12. 맵 생성 및 검증 계약
- **좌표:** `(x,y)`는 0부터 시작. `0≤x<width`, `0≤y<height`; `x=0/14`, `y=0/12`는 외곽 벽. 플레이어 스폰 `(1,1)`과 `(13,11)`.
- **고정 장애물:** 내부의 `x,y`가 모두 짝수인 셀 `(2,2)`~`(12,10)`에 기본 바위를 둔다(6×5=30개). 시작 위치를 막지 않는다. 다른 배치도 가능하지만 공정성 검증 필요.
- **상자 후보:** 내부 바닥 143칸 중 고정 바위 30칸과 스폰 안전 칸(각 스폰 및 인접 2방향)을 제외한 칸. 35%는 **후보 칸에만** 적용한다. 전체 195칸의 35%가 아님.
- **스폰 안전 칸:** `(1,1),(2,1),(1,2)` 및 `(13,11),(12,11),(13,10)`을 상자 없이 유지한다. 두 출구는 고정 바위와도 겹치지 않는다.
- **연결성:** 상자를 배치한 뒤 두 스폰 사이에 통행 가능한 경로가 없을 수 있다. 이는 파괴형 게임에서 허용할 수 있지만 **양쪽 모두 최소 한 개의 파괴 가능한 상자에 접근 가능**해야 한다. AI가 이동 불능 상태에 갇히지 않도록 빈칸 BFS로 접근 가능 칸을 검사하고, 불가능하면 재생성한다. 맵의 모든 빈칸 연결을 강제하지 않는다.
- **시드:** 테스트를 위해 난수 생성기에 시드를 전달할 수 있도록 하고, 결함 기록에 시드를 남긴다.
- **추가 맵:** `width`, `height`, `spawnPoints`, `solidCells`, `crateCandidates`, `theme`, `decorations` 스키마를 공유한다. 맵마다 시각 리소스와 배치 데이터는 다르지만 판정 로직은 동일하다.
- **검증 함수:** 맵 크기, 좌표 범위, 중복/겹침, 스폰 안전성, 출구 2방향, 상자 접근성, 에셋 누락을 검증하고 실패하면 명확한 오류 또는 안전한 기본 맵으로 폴백한다.

## 13. 입력·상태·리소스 관리
- 플레이어별 이동 쿨다운과 설치 한도를 별도로 관리한다. 부적 소유자가 탈락해도 이미 설치한 부적은 제거하지 않는다.
- 게임 상태는 메뉴/라운드별로 명시적으로 생성·폐기한다. 이전 라운드의 키 상태·타이머·이벤트 리스너가 남지 않게 한다.
- Canvas는 480×416 논리 해상도를 유지하고 컨테이너 너비에 맞춰 **정수 또는 유효한 비율로 확대**한다. CSS `image-rendering: pixelated`, 종횡비 고정, HUD는 별도 DOM으로 처리한다.
- 게임 에셋은 프로젝트 내부 상대 경로로 로드한다. 실패 시 기본 도형을 그려 게임을 지속한다. 서드파티 이미지·사운드는 출처와 라이선스를 기록한다.
